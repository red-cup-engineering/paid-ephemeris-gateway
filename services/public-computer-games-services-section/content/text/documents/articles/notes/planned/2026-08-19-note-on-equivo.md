# Equivo

**Status: planned — no code exists.** No service, no lesson corpus, no `equivo-service` package
anywhere in the tree. The checker math it would call is real and already runs (see below); the
game built on top of it is not.

## Concept

"Duolingo for mathematics," teaching a player to observe equivalence by measuring obstruction
rather than by rote symbol manipulation. The learner runs a real four-stage descent —
**articulate → predicate → posit → settle** — against `@lenticule-science/metrologic`'s actual bilattice and
obstruction code, not a simulated approximation of it. Six exercise types are specified
(distinguish / relate / measure / settle / observe / repair) across four presentation-register
lenses (obsmetrologia, semiotics, relationality, and an honestly-absent Lakotaean lens pending
owner-authored source material that does not yet exist). It rides the same Self-Education Platform
chassis Lantern already substantially is.

## Staircase tier

**Later.** The design's own MVP cut explicitly defers Type F exercises, the Lakotaean register,
and the lesson corpus itself, each with a named blocking reason — none a scheduling matter a
roadmap can shrink. This is not "not yet scheduled," it is "blocked on content that doesn't exist."

## Smallest first step

Author one real lesson (one worked descent: articulate → predicate → posit → settle) for a single
concrete equivalence claim, run entirely against real `@lenticule-science/metrologic` code with printed output —
the same discipline `equivo-design.md` §5's three worked examples already model — before writing
any `Checker` interface code. The blocking resource is one authored lesson, not one line of
infrastructure; the platform chassis it would run on (Lantern's five modules) already exists.
